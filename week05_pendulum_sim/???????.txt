一、意图清晰度反思
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
今天最“翻车”的一次，其实不是 AI 把代码写错了，而是我在【任务一】让 AI 初始化
Git 仓库时，脑子里默认环境里已经装好 Git、也已经是现成仓库了。结果一跑才发现：
本机压根没装 Git，文件夹还是空的。回头看我当时那条 Prompt，四段式里“约束 /
验收标准”只写了“确认子目录纯净、Git 基线锁定”，却没把“本机需预装 Git、当前
需是仓库根目录”这种环境前提写进去——AI 缺了这一块就只能自己脑补，自然走歪。

后来我补了一句“先帮我装 Git，再把姓名学号填进去”，AI 才把路走通。一句话总结：
验收标准里得把环境前提也当成约束写清楚；角色 / 目标 / 约束 / 验收 这四段式，缺
哪一段 AI 就会瞎猜，结果就不符合预期。

二、闭环控制反思（ReAct 自愈）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【任务四】练的就是“抓红字”。我按 F12 打开浏览器控制台，点一下“重置”按钮，
真蹦出一行红字：Uncaught ReferenceError: resetAnimation is not defined。
我把这整段堆栈直接甩给 AI，它一分析就点出根因：按钮上写的是内联属性
onclick="resetAnimation()"，这种写法只在全局作用域里找函数；而我那个复位函数
是写在 (function(){ ... })() 这个闭包里的，根本没挂到 window 上，所以全局找不到
它 → 报错。

AI 的修法是改成在闭包里用 addEventListener 来绑定点击，函数本来就在当前作用域
内，自然就不再报错了。我算是真看懂了：这次不是物理公式写错，是“事件绑定方式”
踩了作用域的坑——把内联 onclick 换成 JS 里的 addEventListener 监听，问题就没了。
证据驱动反馈确实比一句“怎么坏了重写”管用太多。

三、主体地位确认（HOTL，人在回路之上）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
我扮演的是“总设计师 + 质量裁判”：今天双摆到底做不做、参数给多少（L=200、g=9.8、
初始 45°）、要不要加滑块 / 拖拽 / 重置按钮、验收怎么算（控制台 0 报错、翻转不
发散），这些都是我拍板的；连“进阶挑战选双摆混沌”也是我提的需求。

AI 扮演的是“施工队”：所有具体的语法、RK4 那堆微分方程、Canvas 发光和彩虹拖尾
的绘制、还有 Git 提交这些重复体力活，全让它干。我最大的收获就是——人负责定方向
和质量标准，AI 负责把意图翻译成能跑的代码，最后效果好不好、达不达标，还是我说
了算。这就是“人在回路之上”的意思吧。
